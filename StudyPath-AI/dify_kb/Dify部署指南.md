# StudyPath · Dify 云端部署指南

## 目标
把已验证的 RAG 能力套进 Dify 可视化壳，做成一个可分享的在线对话 Demo：打开链接即可提问，
答案基于同一套三库知识库。

## 前置
- dify.ai 账号
- 阿里云 DashScope API Key（现有，复用 StudyPath 的 key：qwen-plus + text-embedding-v3）

## 步骤
1. 注册登录 dify.ai，进入控制台。
2. 配置模型供应商（Dify 0.2.9 直接内置「通义」插件，比 OpenAI 兼容模式更简单）：
   - 设置 → 模型供应商 → 找到「**通义**」（带阿里云标识）→ 点右侧「**配置**」或「**+ 添加模型**」
   - **加 LLM**：模型类型选「LLM」→ 模型名选 `qwen-plus`（下拉里通常有，也可手输）→ API Key 填你的 DashScope Key（sk- 开头）→ 保存
   - **加 Embedding**：再点「+ 添加模型」→ 类型选「TEXT EMBEDDING」→ 模型名 `text-embedding-v3` → 同 Key → 保存
   - （可选）类型「RERANK」也加一个 `gte-rerank` 之类，可显著提升检索精度
   - 注意：Dify 插件已默认填好 API Base = `dashscope.aliyuncs.com`，无需手填
   - 不再走 OpenAI 兼容模式——Dify 原生通义插件已内置，你当前截图就是这条路 ✅
3. 创建知识库：
   - 知识库 → 创建 → 上传文件，选本目录下三个 .md
   - 分段：默认按 Markdown 标题（已用 `##` 分段），TopK 建议 4-6，Score 阈值 0.5 左右
   - 索引：高质量（用上面配的 text-embedding-v3）
   - 等待向量化完成
4. 创建应用（**选 Chatflow，不是聊天助手**）：
   - 工作室 → 创建空白应用 → 类型选「**Chatflow**」→ 命名「StudyPath 留学规划助手」→ 创建
   - **节点搭建（关键）**：
     - 拖 3 个「**知识检索**」节点，每个都从「开始」节点拉线出来（并联），分别绑定：
       - 知识检索·院校 → StudyPath-院校项目库，查询变量 `sys.query`
       - 知识检索·案例 → StudyPath-录取案例库，查询变量 `sys.query`
       - 知识检索·文书 → StudyPath-文书范例库，查询变量 `sys.query`
       - 每个节点 TopK=3
     - 拖 1 个「**LLM**」节点，把三个检索节点的输出线都连到它；模型 `qwen-plus`，记忆窗口开 5-10 轮
     - 拖 1 个「**直接回复 / 结束**」节点，连在 LLM 后，输出选 LLM 文本
   - **✅ 上下文自动注入机制（已验证 2026-08-18 跑通）**：在 Dify Chatflow 中，**只要把知识检索节点直接连到 LLM 节点，检索结果会自动作为上下文注入 LLM，无需任何手动配置**。LLM 节点「上下文」那个下拉是给"额外再加一段"用的（如要再手动塞变量），不是必填。Prompt 编辑器变量面板不显示上游节点输出也不影响自动注入。
     所以**最简结构就是**：开始 → 3 知识检索并联 → LLM → 直接回复，无需加模板转换节点。
   - LLM 节点配置：
     - 模型：`qwen-plus`
     - 记忆窗口：5-10 轮（开启多轮对话）
     - 「上下文」区域：留空即可（已自动注入）
     - USER 提示词结构（与线上部署版一致）：固定开头 + 三路检索结果占位 + 用户问题变量 + 规则列表。开头写「你是 StudyPath AI 留学申请规划助手，请严格基于下方三路检索资料回答用户问题。」，随后依次放三个检索结果变量的占位、`{{#sys.query#}}`（从变量面板选「开始/sys.query」插入），最后是规则。
     规则（写在 LLM 的 USER 提示词里，2026-10-13 与线上部署版逐条核对一致）：
     1. 当用户问【申请要求/录取门槛/GPA/托福/雅思/GRE/截止日期】→ 引用「院校库检索结果」
     2. 当用户问【我背景够不够 / 录取可能性 / 类似案例】→ 引用「录取案例库检索结果」
     3. 当用户问【SOP/PS/CV/简历/文书模板/范例链接/写作指导】→ 必须且只能引用「文书库检索结果」
     4. 其他问题按相关性综合引用三库；**只有在检索结果确实为空**时才可以说"该信息未在知识库覆盖"并建议去官网核实；检索结果里有院校/案例就照常给出，不得拒答
     5. 用 ### 小标题 + - 列表呈现
     6. 末尾附 [资料N] 引用（对应 source_url）
     7. 面向具体申请者说话，像顾问给建议一样直接给结论；不要写"在数字化浪潮席卷全球的今天"这类宏观铺垫式开场，也不要写成泛泛而谈的通用说明文
     8. 不要向用户展示知识库或内部模块的名称（如"院校库""录取案例库""文书库"），也不要暴露内部工作流程；一律改用「申请要求」「录取案例」「文书范例」这类业务说法
     9. 判断"最新/当前申请季"一律以系统当前日期为锚，不得把知识库里出现的最大年份当作"最新"。截止日期已早于当前日期的记录属于往季，**但往季不等于没有数据**：院校的门槛、语言要求、截止日期必须照常完整给出，只在日期后标注「（往季参考，以官网为准）」，并在开头说明一句"知识库收录的是 20XX 申请季的信息，最新以官网为准"；**严禁因为申请季已过就回复"未覆盖"或拒绝推荐院校**
     （1–3 是**三库路由分流**，对应本地主链 LangGraph 的 supervisor 路由；4–6 是事实与格式；7 是语体；8 是防内部信息外泄；9 是时间口径——8、9 都是主链已有、Dify 侧原来缺的约束。）
   - 调试：右上「运行」输入测试题，确认三个检索节点各自召回 + LLM 跨库汇总；再追问一句验证多轮记忆（如"那 CMU 的 GPA 要求多少？"）
5. 调试：输入测试问题，确认召回片段正确、回答带 source_url
6. 发布：点发布 → 获得公开 URL，发给老师/评委

## Prompt 模板（贴到应用编排的「指令」里）
```
你是 StudyPath 留学规划助手。严格基于【知识库】内容回答用户关于留学申请的问题。
规则：
1. 只用知识库里的事实，绝不编造院校/排名/分数/录取案例。
2. 知识库不足时如实说明，并建议补充哪类数据。
3. 面向具体申请者说话，像顾问给建议一样直接给结论；不要写"在数字化浪潮席卷全球的今天"这类宏观铺垫式开场，也不要写成泛泛而谈的通用说明文。
4. 用中文、条理清晰，用 ### 小标题 + - 列表呈现。
5. 每条事实附上来源链接（source_url / 来源）。
6. 覆盖三类问题：院校推荐、背景匹配评估、文书范例。
```

> 注：上面这段是**应用级「指令」（system 角色）**，定角色与总原则；LLM 节点 USER 提示词里的 6+1 条定的是**三库路由与输出格式**（见上一节）。两处不是同一处、互不冲突，可同时存在。

## 与本地主链的口径对齐（语体同步）

本地主链（`rag/qa.py` 单链、`rag/agents.py` 三个 worker + 整合器）在实验①之后加了一条语体规则：
「面向具体申请者说话、像顾问给建议一样直接给结论，不写宏观铺垫式开场」。
Dify 这条链路是对外出口，提示词必须跟主链共用同一套规则，否则同一个项目从两个入口问会得到两种腔调。

同步范围（改哪儿、为什么）：

| 环节 | 是否改 | 原因 |
| --- | --- | --- |
| Dify LLM 节点提示词 | **要改** | 它是这条链唯一生成文字的地方，追加第 7–9 条（语体 + 防内部信息外泄 + 时间口径）即可齐 |
| 事实铁律（不编造 / 不足则说明 / 附来源） | 已一致 | 第 4–6 条本就覆盖，无需改动 |
| N8N 工作流 | **不用改** | N8N 没有 LLM 节点，它只是 `HTTP Request` 调 Dify API → `Edit Fields` 提取 answer → 推飞书。推给群里的文字就是 Dify 的返回，改 Dify 自动改到了飞书 |

⚠️ 「运行独立」和「口径统一」是两件事：Dify 在云端跑、主链在本地跑，运行时拓扑各自独立（PPT 第 11 页的说法）；但对外交付给用户的回答应当出自同一个顾问口径。

操作路径（逐层）：登录 dify.ai → 右上角进入 **工作室** → 打开应用 **StudyPath 留学规划助手** → 右上 **编排** → 画布上点 **LLM** 节点 → 右侧面板 **USER 提示词** 框 → 在**规则列表的最后追加**下面这一条 → 右上 **发布** → **更新**。

要追加的规则（可直接粘贴；第 7 条你已贴过，从第 8 条继续贴；第 10–12 条见下文「事实保真加固」节。**第 9 条已于 2026-10-14 修订**——旧版会把"往季数据"直接判成"未覆盖"而拒答，务必用下面这版覆盖）：

```
8. 不要向用户展示知识库或内部模块的名称（如"院校库""录取案例库""文书库"），也不要暴露内部工作流程；一律改用「申请要求」「录取案例」「文书范例」这类业务说法。
9. 判断"最新/当前申请季"一律以系统当前日期为锚，不得把知识库里出现的最大年份当作"最新"。截止日期已早于当前日期的记录属于往季，但往季不等于没有数据：院校的门槛、语言要求、截止日期必须照常完整给出，只在日期后标注「（往季参考，以官网为准）」，并在开头说明一句"知识库收录的是 20XX 申请季的信息，最新以官网为准"；严禁因为申请季已过就回复"未覆盖"或拒绝推荐院校。
```

⚠️ 核对线上部署版（面板顶部显示「已发布 2 个月前」）时，USER 提示词的**实际结构**是「三路检索结果 → 用户问题 `{{#sys.query#}}` → **6 条规则**」：前 3 条是三库路由分流（申请要求/门槛/截止日→院校库；背景与案例→案例库；文书→文书库），第 4–6 条是事实与格式。**上一节的模板已按这个实际结构对齐**，不再另设一套。
**所以一律"末尾追加第 7–9 条、不插中间、不给已有规则重新编号"**——插到中间会打乱路由顺序，把分流逻辑切断。

## 事实保真加固（2026-10-14 实跑暴露）

### 现象
用「我是双非本科，GPA 3.6，托福 100，申请美国计算机硕士，帮我推荐学校，并告诉我各校的申请截止日期」实跑，Dify 输出事实层大面积失真：

| 输出写的是 | 院校库原文 |
| --- | --- |
| UCI **MS in Computer Science** | Master of Computer Science (**MCS**) |
| UCI GPA **3.5+** / 托福 **100+** | **3.6** / **80** |
| UCI GRE「强烈建议、均分 **322+**」 | **Not Required / Optional** |
| UCI 截止 **2025年**12月15日 | **Dec 15**（原文无年份，被自行补了年份） |
| UCSC GPA **3.3+** / 截止 **2025年12月10日** | **3.0** / **Jan 10 / Jan 24 / Jan 26** |
| NEU GPA **3.4+** / 托福 **100+** / 截止 **2025年12月1日** | **3.0 / 90 / Fall Intl May 1 (Rolling)** |
| **University of Texas at Dallas** | 库里没有这所学校（只有 UT Austin、Texas A&M） |

另有「近 3 年无拒录记录」「100% 有 6 个月以上实习」「双非录取占比 38%」「GRE 提交者超 70%」「2026 Fall 起永久豁免」「毕业生平均起薪 $105K」等——**这些字段知识库里根本不存在**，是模型凭常识补的。

### 根因（三条，和主链踩过的坑同源）
1. **Dify 只有提示词约束，没有确定性事实注入**。主链的 `_gate_block`（逐校硬比对门槛）+ `_deadline_block`（截止日原文清单）是 Python 代码，Dify 侧没有等价物，全靠 qwen-plus 自觉。
2. **TopK=3 召回太少**：每次只召回 3 所院校，模型为了凑出「冲刺/匹配/保底」三档，会拿记忆里的学校补齐。
3. **提示词里没有当前日期**：第 9 条要求「以系统当前日期为锚」，但模型并不知道今天是几号，只能锚到知识库里的最大年份（2026），于是把已经过去的 2025 年 12 月截止日当成待办输出。

### 修复 A：追加第 10–12 条（必做，改提示词即可）
在第 9 条之后**末尾追加**（不插中间、不重编号）：

```
10. 只能推荐【检索结果】中实际出现的院校；不得凭常识补充检索结果之外的学校。入榜的院校数=检索到的院校数，不够三所就少推荐，宁可只给一所，也不要为了凑满三档而补学校。
11. 院校的 GPA / 托福 / 雅思 / GRE / 截止日期必须逐字照抄检索片段原文：不得四舍五入、不得改写措辞、不得补年份（原文写「Dec 15」就写「Dec 15」，不许写成「2025年12月15日」）。
12. 不得输出检索片段中没有的字段：录取率、就业率、平均起薪、师生比、实习占比、「近N年无拒录」「永久豁免」等一律不写；没有的字段就不提。也不得编造申请流程细则（如「不接受邮件补交」「需额外上传预算说明」）。
```

同时把三个知识检索节点的 **TopK 从 3 调到 6**（设置 → 该节点 → TopK）——召回池大一点，模型就没有理由去补校。

### 修复 B：加「代码」节点（推荐，这才是与主链真正对齐）
修复 A 能把编造压下去大半，但做不到确定性。要让答辩时说得出「Dify 与主链同口径」，得像主链一样把事实**算出来再喂**：

**B1 注入当前日期**（让第 9 条真正生效）
在「开始」节点后加一个 **代码** 节点，输入留空，输出变量名 `today`：

```python
def main(args):
    from datetime import datetime
    return {"today": datetime.now().strftime("%Y-%m-%d")}
```

然后在 LLM 节点的 USER 提示词**开头**加一句：`今天是 {{#代码节点.today#}}，判断「最新/当前申请季」一律以该日期为锚。`

**B2 抽取院校事实清单**（等价于主链 `_gate_block` + `_deadline_block`）
再加一个 **代码** 节点，把三路「知识检索」节点的输出都连到它；输出变量名 `facts`：

```python
def main(args):
    import re

    def txt(x):
        if isinstance(x, list):
            return "\n".join(str(i.get("content", i) if isinstance(i, dict) else i) for i in x)
        return str(x or "")

    text = "\n".join(txt(args.get(k)) for k in ("school_ctx", "case_ctx", "essay_ctx"))
    rows = []
    for block in re.split(r"\n(?=##\s)", text):
        if "申请截止" not in block:
            continue
        name = re.search(r"##\s*(.+?)(?:\s*·|$)", block, re.M)
        def field(label):
            m = re.search(r"-\s*" + label + r"[：:]\s*(.+)", block)
            return m.group(1).strip() if m else "未收录"
        if not name:
            continue
        rows.append("- %s：申请截止 %s；GPA最低 %s；托福最低 %s；雅思最低 %s；GRE要求 %s" % (
            name.group(1).strip(), field("申请截止"), field("GPA最低"),
            field("托福最低"), field("雅思最低"), field("GRE要求")))
    body = "\n".join(rows) if rows else "（本次检索未命中院校记录）"
    return {"facts": "【院校事实清单·以下为硬事实，只能逐字照抄，不得改写、不得补年份】\n" + body}
```

接线（**两个代码节点接法不同，别搞混**）：

| 节点 | 输入来自 | 输出到 | 输出变量 |
| --- | --- | --- | --- |
| **代码①`today`** | 只接 `开始`（**不要接知识库**） | `LLM` | `today` |
| **代码②`facts`** | **三个知识检索的输出**（`school_ctx` / `case_ctx` / `essay_ctx`） | `LLM` | `facts` |

**代码②的输入参数绑定**（点代码节点右侧面板「输入变量」的 `+`，逐个加，变量名必须与脚本里 `args.get()` 的 key 一致）：

| 变量名 | 值选 |
| --- | --- |
| `school_ctx` | `知识检索 / result`（院校项目库那个） |
| `case_ctx` | `知识检索2 / result`（录取案例库） |
| `essay_ctx` | `知识检索3 / result`（文书范例库） |

⚠️ **三路检索的原文片段仍然要各自直连 `LLM`**（不能只连 facts）。Chatflow 的「检索结果自动注入」靠的就是那条直连线，断了 LLM 就拿不到原文，第 6 条的 `[资料N]` 溯源会一起失效。所以是**两条腿**：检索 →(原文)→ LLM，检索 →(抽成清单)→ facts → LLM。

接线完成后的完整拓扑：

```
开始·用户输入
  ├─→ 代码① today ─────────────────────────┐
  ├─→ 知识检索1 院校 ──┬─→ 代码② facts ──→ │
  ├─→ 知识检索2 案例 ──┤                    ├─→ LLM ─→ 直接回复
  └─→ 知识检索3 文书 ──┴──────────────────→ ┘
                        （原文片段直连 LLM）
```

然后把 `{{#代码②节点名.facts#}}` 插到 USER 提示词里三路检索结果之后、规则列表之前（节点名以画布上实际显示为准，默认叫「代码执行」就叫 `{{#代码执行.facts#}}`），并补一句：`凡提到清单内院校的申请截止日与门槛，必须逐字复制清单里的值，不许自己生成日期、不许补年份、不许把某校的值挪给另一校。`

`today` 的用法：在 USER 提示词**开头**加 `今天是 {{#代码执行.today#}}，判断「最新/当前申请季」一律以该日期为锚。`

> 两个代码节点只是把主链已有的两道确定性兜底搬到 Dify 画布上，不改变拓扑叙事（仍是三库隔离检索 + 跨库汇总），反而让「代码 + 拖拽双对照」这条答辩线更硬。

## 二次实跑：加了规则反而只回「未覆盖」怎么办（2026-10-14）

### 现象
追加第 10–12 条后，同一道题（双非 GPA3.6 托福100 申美国 CS）Dify 只回：
> 该信息未在知识库覆盖。请前往目标院校官网查看最新申请要求与截止日期，或提供具体院校名称，我可帮你核对已收录的申请细节。

**这不是改坏了，而是规则开始生效的证据。** 改之前它敢一口气列 5 所学校并附门槛与截止日，是因为它**根本没在看检索结果**、纯凭记忆在编（所以才会凭空造出 UT Dallas、把 UCI 的 GPA 3.6 写成 3.5+）。规则 10 禁止"推荐检索结果之外的院校"之后，模型手里一没料就老实了。

### 两个成因（按可能性排序，都要查）
1. **规则 9 旧版把"往季"判成了"没有"（已修订，最常见）**：今天是 2026-10-14，知识库截止日全是 2025-12（对应 2026 Fall，已过）。旧版规则 9 写着「知识库未覆盖当前申请季时，如实说明知识库收录为往季数据」，模型直接理解为"库里没有你要申请的那一季" → 触发规则 4 的模板句「该信息未在知识库覆盖」。
   **注意**：输出里那句「或提供具体院校名称，我可帮你核对**已收录的**申请细节」说明模型**知道库里有院校细节**——所以多半不是检索空召回，是时间口径判过头了。
2. **检索真的空召回**：Score 阈值卡掉了全部片段，或查询太长太多意图导致相似度低。

### 一锤定音的排查方法（30 秒）
在 Dify 调试面板里，**点那条回复气泡上方「直接回复 ＞」右侧的箭头**展开节点执行记录 →
依次看三个「知识检索」节点的**召回条数与片段内容**，再看 LLM 节点收到的**上下文**：
- 召回有内容、上下文也有 → 是**规则 9 判过头**，按上文修订版覆盖第 9 条即可；
- 召回 0 条 / 上下文为空 → 是**检索侧问题**：
  - 把三个知识检索节点的 **Score 阈值关掉（设为 0）或降到 0.2**，TopK 保持 6；
  - 把长问句拆短再试（用「UCI 的 GPA 和托福要求是多少」验证链路是否通）；
  - 确认「知识检索」节点确实有连线进 LLM（Chatflow 里检索结果会自动注入，但只要断线就静默为空）。

### 三次实跑（10:53）：模型自己承认「暂无检索结果」——检索侧实锤

第三次同一道题，Dify 回：

> 该信息未在知识库覆盖。知识库中暂无针对"美国计算机硕士"项目的院校申请要求（含GPA、托福、截止日期等）的**检索结果**，也未收录匹配双非背景、GPA 3.6、托福 100 的美国CS项目录取案例或相关文书范例。

它**明确说了三路检索都没结果**，并顺手拿常识推荐了东北大学 / 伊利诺伊理工 / UCI / 南卫理公会大学（库外或未经检索的校名）——**根因在检索，不在规则**。上文修订第 9 条仍然要做（往季≠未覆盖），但它不是这一条的解。

⚠️ **"以前看起来能用"是假象**：检索为空时模型照样能凭记忆编出 5 所学校并附门槛与截止日。是加了"只能用检索结果中的院校"规则之后，才把"检索可能从来没通"这件事暴露出来。

按顺序排查（前两条能解决绝大多数情况）：

1. **Score 阈值**：三个知识检索节点的 Score 阈值 → 设为 0 或 0.2（0.5 会卡掉中文长问句）；TopK 保持 6。
2. **知识库索引状态**：去「知识库」页面看三个库的**文档数 / 分段数 / 索引状态**是否正常（状态须为「可用」）。
   **特别注意**：2026-10-13 出现过 DashScope `code=Arrearage` 欠费——若在欠费期间上传或重建过知识库，**embedding 会失败、索引可能是空的**。欠费解决后需进库里点「重新索引 / 重新向量化」。
3. **短查询验证**：输入「UCI 的 GPA 要求是多少」——能答 = 长问句召回问题；仍不能答 = 索引或连线问题。

### 兜底：加一条防拒答
若修订第 9 条后仍偶发拒答，可在 rules 末尾再补一句：

```
13. 只要检索结果里出现了任何院校记录，就必须把该校的门槛与截止日完整给出（标注往季参考），不得以"申请季已过""信息可能不准"为由拒答或只回"未覆盖"。
```
