# StudyPath AI 项目需求与功能说明

>   基于代码与数据事实整理，无虚构数据。

---

## 一、背景与价值

### 1.1 痛点

在我们留学申请过程中，学生需要同时处理大量的分散信息：

- **院校信息分散**：各项目官网格式不一，GPA、语言、GRE、截止日期、学费、偏好背景等关键字段散落在不同页面，人工整理耗时。
- **录取案例难对标**：不知道自己 GPA/语言/科研背景能申到什么层次的学校，缺乏同背景案例参考。
- **文书没有参照**：PS/SOP/CV 怎么写、突出什么、避坑什么，缺少可溯源的范文与结构参考。
- **决策周期长**：学生往往需要反复搜索、对比、记录，容易遗漏 deadline 或 mismatched 项目。

### 1.2 价值

| 维度 | 传统方式 | StudyPath AI |
|------|---------|--------------|
| 信息搜集成本 | 人工翻阅多个官网/论坛，数小时 | 自然语言一句话提问，秒级召回 |
| 选校匹配效率 | 靠经验/中介，主观性强 | RAG 基于真实录取案例做背景对标 |
| 文书准备效率 | 无范文参照，从零写 | 检索范文库，给出结构与避坑建议 |
| 决策可靠性 | 容易记错 deadline/要求 | 每条信息都带 `source_url`，可点击核验 |

**核心落点**：用 RAG + 多智能体把留学申请的信息检索、选校匹配、文书准备三个高频环节自动化，降低学生时间成本，提升决策质量。

## 二、核心功能清单

### 2.1 RAG 问答系统

- **三库检索**：院校项目库（100 条）、录取案例库（50 条）、文书范例库（30 条），合计 180 条真实记录。
- **别名归一化**：支持 "CMU/帝国理工/港大" 等 37 所学校的中英文口语化简称，先归一再检索，提升召回率。
- **MMR 检索策略**：先按余弦相似度粗捞 20 条，再用 MMR 精挑 8 条，兼顾相关性与多样性。
- **来源可追溯**：每条检索结果都来自真实 `source_url`，驾驶舱底部以参考来源卡片形式列出，可点击核验。

### 2.2 LangGraph 多智能体调度

- **Supervisor（调度器）**：LLM 判断用户问题需要哪些专家。
- **三个 Worker（专家）**：
  - `school`：负责院校排名、申请要求、截止日期、学费。
  - `admission`：负责录取案例与背景匹配。
  - `essay`：负责文书范文与写作建议。
- **Synthesizer（综合器）**：汇总三库检索结果，生成带引用的三段式回答（目标校推荐 / 行业建议 / 不建议项目）。
- **当前实现**：三个 Worker 链式串行，简单可控；检索不是耗时瓶颈，瓶颈在 Synthesizer 生成。

### 2.3 学术驾驶舱（Gradio 前端）

- **Profile Snapshot**：从用户 query 自动抽取 GPA、语言成绩、科研/实习、目标国家/专业/学校。
- **Fit 分析**：根据画像与检索到的项目要求做匹配度评估。
- **多维展示**：推荐结果、申请路线图、院校地图、申请策略建议。
- **路由可视化**：显示 Supervisor 派了哪些 Worker，让系统决策可解释。
- **参考来源卡片**：LLM 答案末尾展示 `[资料N]` 引用，底部列出可点击的真实来源链接。

### 2.4 Dify 低代码 MVP

- 在 Dify 上发布了一个独立的留学问答 Chatbot（`udify.app/chat/...`）。
- 验证同一知识库在低代码平台上的快速落地能力。

### 2.5 N8N 自动化工作流

- 本地 Docker 部署 N8N。
- 实现 HTTP Request 调用 Dify API，形成"输入问题 → 调用 Dify → 返回结果"的自动化闭环。
- 可用于后续扩展：定时提醒、材料清单推送、新数据自动入库。

### 2.6 LoRA 微调（文书生成方向）

- 目标：针对留学文书生成任务微调 Qwen2.5-7B-Instruct。
- 方案：LoRA rank=8 / alpha=16，学习率 2e-4，3 个 epoch，batch=1/grad_accum=8。
- 数据：180 条真实留学相关记录（含文书范例）。
- 环境：AutoDL RTX 3090 单卡，纯训练时间约 106.8 秒，train_loss 1.2962 → eval_loss 0.7597，收敛未过拟合。
- 产物：`model/lora/adapter_model.safetensors`（约 20MB）。

## 三、技术栈

| 层级 | 技术 |
|------|------|
| 大模型 API | DashScope qwen-plus（走 OpenAI 兼容端点） |
| 嵌入模型 | DashScope text-embedding-v3 |
| 向量库 | Chroma（本地持久化） |
| RAG 框架 | LangChain + 自实现 `DashScopeEmbeddings`（走原生 SDK 避兼容层 400） |
| 多智能体编排 | LangGraph StateGraph，手写 Supervisor-Worker-Synthesizer |
| 前端 | Gradio 4.x，自实现学术驾驶舱 UI |
| 低代码 MVP | Dify |
| 自动化工作流 | N8N（本地 Docker） |
| 微调框架 | LLaMA Factory + LoRA |
| 数据处理 | openpyxl、pandas |

## 四、数据规模与来源

| 库 | 条数 | 字段示例 | 来源要求 |
|----|------|---------|---------|
| 院校项目库 | 100 | 学校、项目、GPA/托福/雅思/GRE、截止日期、学费、排名 | 每条必须带 `source_url` |
| 录取案例库 | 50 | 背景、录取结果、项目、年份 | 同上 |
| 文书范例库 | 30 | 文书类型、结构、亮点、避坑 | 同上 |
| **合计** | **180** | | **全部真实可溯源，禁止虚构** |

- 数据来源：学校官网、QS、USNews、一亩三分地等公开渠道，人工采集整理成 Excel。
- 别名表：37 所高频学校的中英文别名映射，解决口语化查询召回问题。

## 五、量化成果

| 指标 | 数值 | 说明 |
|------|------|------|
| 对抗集 HitRate@8 | 100% | 15 道口语化/别名/模糊查询全部召回 |
| 对抗集 MRR | 0.933 | 首个相关文档平均排名 |
| 生成忠实度 | 100% | 回答事实均能在检索资料中找到 `source_url` |
| 路由覆盖率 | 100% | 该派 Worker 时全部派到 |
| 路由精确率 | 63.3% | Supervisor 倾向多派保召回，宁可多查不可漏查 |
| 延迟 P50 / P95 | 2.67s / 9.04s | RAG 单次问答延迟 |
| LoRA 训练时间 | ~106.8s | RTX 3090 单卡，51 steps |
| LoRA loss | 1.2962 → 0.7597 | train_loss / eval_loss，收敛未过拟合 |

## 六、项目边界（做了什么 / 没做什么）

### 已做
- 基于真实 180 条留学数据构建 RAG 知识库。
- LangGraph 多智能体问答链路可运行。
- Gradio 学术驾驶舱可本地演示。
- Dify MVP 已发布、N8N 自动化链路已跑通、LoRA 权重已训练。
- 评测体系与量化指标已落地。

### 未做（后续可扩展）
- 多模态 OCR 解析用户简历/成绩单（架构里可接入，当前未实现）。
- 自动化的申请 deadline 提醒与材料清单推送（N8N 可扩展）。
- 更重的 Rerank 模型（当前用 MMR，未接入独立 Rerank）。
- Worker 并行化（当前链式串行，理论上可并行）。
- 用户登录与会话历史持久化（当前单轮无状态）。

---

## 七、一句话总结

StudyPath AI 是一个面向留学申请场景的 **RAG + 多智能体规划助手**：用 180 条真实可溯源数据构建知识库，通过 LangGraph 调度三个领域专家 worker，在 Gradio 驾驶舱里提供画像分析、选校匹配、文书建议，并配套 Dify MVP、N8N 自动化、LoRA 微调三个模块，最终目标是降低学生留学申请的信息搜集与决策成本。
